01处理流程 / Workflow

从描述问题，到可核对的答复

LangGraph 串起分诊、检索、证据判断和答复分支。每一步都有明确的职责与失败出口。

  1. 识别问题与风险

    根据标题与描述判断工单类别、优先级和风险。涉及生产、支付、权限等敏感问题时，保留人工处理边界。

  2. 检索知识，保留来源

    使用 SQLite FTS5 与 BGE 向量检索能力，按评测策略选择召回方式。结果保留文档版本、分块编号与原文摘录。

  3. 选择合适的处理路径

    风险分诊与证据判断保留在原 Agent 链路中。限定范围内的低风险问题可以进入只读辅助模式；信息不足先追问，敏感或不支持的问题直接转 IT。

  4. AI 排查与继续追问

    MiMo 结合最新情况与知识来源，给出适用的下一步或追问关键缺失信息。服务端检查引用与建议，避免重复已尝试无效的步骤；员工补充在同一工单继续，必要时带着记录转 IT。

  5. 保存结果，继续跟进

    员工确认解决后关闭工单；仍未解决可以联系 IT。管理台默认查看人工队列，先呈现问题、接管原因与已有补充，减少重复问询；员工可以查看回复、确认或重新打开。

02功能与边界 / Capabilities

建议可追溯，处理有边界

员工与跟进

员工通过账号登录，只查看自己的工单。AI 建议与追问、IT 回复和处理状态按时间展示；补充、确认、转人工和重开都在原工单中完成。旧浏览器凭据单独保留。

员工账号隔离状态记录

知识与版本

维护知识文档、分块和版本；检索保留来源信息，避免把无依据的回答当成处理结论。

FTS5BGEsqlite-vec

审批与交付

软件安装与设备借用按版本化演示规则自动批准、拒绝或转人工；获批后由 IT 确认安装或库存安排并交付，员工验收后关闭。敏感申请保留人工审批。

风险分诊引用校验

管理与运行

管理员使用账号、密码与人机验证登录。人工队列、获批待交付、审批规则、知识库和系统指标分开；处理人来自服务端身份，内部评分与检索资料收起，员工页面聚焦回复与进度。
