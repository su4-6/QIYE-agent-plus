# 系统架构

```mermaid
flowchart LR
    U[公开访客] --> API[FastAPI]
    A[管理员] --> API
    API --> AUTH[访问凭证 / 管理员会话 / 租户过滤]
    AUTH --> G[LangGraph 工单流程]
    G --> T[意图与风险识别]
    T --> Q[术语归一与查询改写]
    Q --> B[SQLite FTS5 / BM25]
    Q --> V[sqlite-vec / 中文向量]
    B --> R[RRF 融合与业务信号重排]
    V --> R
    R --> E{低风险且证据充分且发布门槛通过}
    E -->|是| L[MiMo / 受约束的大模型生成]
    L --> C[引用集合 / 租户 / 文档版本校验]
    E -->|否| H[人工处理]
    C -->|生成失败或引用无效| H
    C -->|通过| O[返回有来源的建议]
    H --> DB[(SQLite 工单与审计)]
    O --> DB
    DB --> M[管理员检索健康面板]
    API --> TRACE[请求ID与结构化日志]
    R --> EV[隔离评测 / 校准阈值 / 独立测试]
    EV --> GATE[自动建议发布保护]
    GATE --> E
```

## 核心边界

- `tenant_id` 只由服务端会话决定，不接受请求参数中的租户值。
- 公开访客凭创建工单时返回的随机凭证读取自己的工单；数据库只保存凭证哈希。
- 管理员使用签名、限时、HttpOnly 的会话 Cookie，写操作还需要 CSRF 令牌。
- 高风险或证据不足的工单不会显示为已自动执行，只进入人工处理状态。
- 模型只能引用本次检索返回的段落 ID；服务端再次校验引用与租户归属。

## 评测与运行状态

- 旧关键词算法冻结在 evaluation 中，生产代码只使用 knowledge 检索入口。两路检索当前依次执行，不宣称并发搜索。
- sqlite-vec 对当前租户有效向量做精确余弦扫描；RRF及业务信号为轻量规则重排，没有ANN或Cross-Encoder。
- 文档分块保留标题路径，按句子切分，超长单句才按长度兜底。引用同时保存文档版本、段落ID和稳定chunk_key。
- 证据评分不是正确概率。阈值只在校准集选择，冻结测试决定是否开放自动建议；当前两种模式均未达到95%测试门槛，默认人工审核。
- 引用有效性不等于语义支持。生成器真实实验保留答案与资料，语义审查单独注明AI审查；不宣称服务端实现了完整事实校验。
- `/health` 检查数据库、向量扩展、模型维度、有效覆盖及最近运行情况。旧索引没有运行验证时明确标为待验证；不在健康检查中下载模型或调用付费服务。
- `/health/live` 只证明进程存活。管理员统计仅覆盖会话租户，缺字段的历史工单单列，不当作零值计入分母。
