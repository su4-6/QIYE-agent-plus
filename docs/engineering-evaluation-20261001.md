# 工程改造与评测结果（2026-10-01）

## 实验条件与复现

Windows 本机、Conda ticket-agent、Python 3.13.13、32 个逻辑 CPU，BGE 使用 CPU 和 2 个推理线程。使用真实 BAAI/bge-small-zh-v1.5 的 **512 维**向量与 sqlite-vec；向量覆盖 60/60，未用字符相似度代替向量。机器同时运行其他桌面应用，未做性能隔离；这里只是短时本地实验。

语料为 AI 辅助编写的 60 个模拟 IT SOP 主题，共 60 段；180 条查询分为 120 条可回答、30 条证据不足、30 条高风险。校准／测试各 90 条，按主题分组，同主题近似问法不跨集合。测试集含 60 条可回答查询，命中率的分母为这 60 条。主题标签经过按资料核对，**没有人工双人标注**，不得称为真实企业工单或人工标注金标准。

所有检索方案读取同一批段落。评测使用临时数据库，不会改动用户工单库；脚本单独导入语料，不调用应用启动时的旧六段种子。稳定计时不包括模型首次加载与语料建索引。向量检索为租户过滤后的精确余弦扫描，未使用 ANN 或专用向量数据库。

```powershell
conda run -n ticket-agent python -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File .\scripts\evaluate-conda.ps1 -Performance
# 真实模型实验需显式开启；每次新实验最多30次请求
powershell -ExecutionPolicy Bypass -File .\scripts\evaluate-conda.ps1 -LiveMimo -Performance
# 本次模型结果已保存；复用这些记录不发送LLM请求
conda run -n ticket-agent python -m evaluation.run --reuse-generation --performance --output evaluation/results/20261001
# 只核验保存结果并刷新哈希清单，不发模型请求、不运行压测
conda run -n ticket-agent python scripts/finalize-evidence.py
```

本次原始证据在 [evaluation/results/20261001](../evaluation/results/20261001)。summary.json 保存运行时间、代码基线及工作树状态、依赖版本、源代码 SHA-256；manifest.json 校验结果文件。代码当时在工作树中改造，不能将 summary 中的旧 HEAD 单独当成此次实现版本；源代码摘要与最终提交共同确定版本。所有数据哈希使用明示的文件内容，源码摘要规范化为 LF。

.gitattributes为评测原始记录与输入JSON禁用Git换行转换，保证Windows与Linux检出后仍能核对相同的文件哈希。

版本顺序：30次真实生成先完成，随后复用结果运行最终检索／HTTP评测，最后补充模型请求前的租户上下文校验与容器静态资料路径修复。后续修改只进行了离线验证，没有追加付费调用。summary中的源码摘要属于检索／HTTP复跑时刻；delivery-validation.json记录最终源码摘要及差异。最初30次调用的源码未单独冻结，因此不能声称其代码与最终交付完全一致。

## 检索对照

| 方案 | Hit@1 | Hit@3 | Hit@5 | MRR@5 | P50 ms | P95 ms |
|---|---:|---:|---:|---:|---:|---:|
| 冻结的旧关键词算法 | 18.33% | 40.00% | 46.67% | 0.2972 | 0.66 | 0.74 |
| FTS5 BM25 | 73.33% | 85.00% | 86.67% | 0.7847 | 20.74 | 39.83 |
| BGE 真实向量 | 90.00% | 93.33% | 93.33% | 0.9167 | 30.63 | 34.81 |
| RRF 混合（无业务重排） | 83.33% | 88.33% | 91.67% | 0.8667 | 43.86 | 58.90 |
| RRF＋业务重排 | 78.33% | 86.67% | 91.67% | 0.8358 | 40.41 | 56.09 |
| 混合关闭改写 | 78.33% | 86.67% | 91.67% | 0.8358 | 42.47 | 57.52 |
| 混合关闭标题信号 | 81.67% | 88.33% | 91.67% | 0.8575 | 42.97 | 60.66 |

同一语料和测试查询上，旧算法 Hit@3 为 24/60，BM25 为 51/60，混合重排为 52/60。混合相对旧算法提升 **46.67 个百分点**，相对 BM25 仅提升 **1.67 个百分点**。不能拿以前六段／30 问上的 100% 与这组数据比较。

本组查询每题只有一个预期主题，因此 Recall@3 与 Hit@3 数值相同；报告仍区分“至少命中一个相关主题”与“覆盖全部标注相关主题”的定义。MRR 截断于前五个候选。

纯向量 Hit@3 达到 56/60，高于混合；关闭标题加权或只用 RRF 后为 53/60，说明现有标题权重具有负收益。查询改写消融未改变本次测试命中率。保留这些结果，未根据已看过的测试集重新调权重。默认混合通过“不得低于 BM25”的预设检索门槛，**并不等于混合是最优方案**。

零召回率以全部 90 条测试查询为分母：BM25 为 12/90，混合为 0/90。负例没有资料时返回空结果可能是正确行为；向量近邻有结果也不意味着有足够证据。旧算法无匹配时会回退到默认段落，所以零召回为零同样不能证明它更好。

另保留用户提供的 18 段／28 问词法对照，在 lexical-reproduction.json 独立复现整词 MATCH、LIKE 与 trigram。它使用内存 SQLite、不同语料与标签，不与上述数字合并。

## 阈值校准与发布保护

证据评分只取首条资料的词覆盖率和有效向量相似度的最大值；不是答案正确概率。校准集排除专门标注的高风险用例，在至少放行20条且证据选择精确率≥95%的条件下，选择覆盖率最大的阈值；并列选更严格阈值。BM25 阈值为 0.4，混合为 0.510423。

| 模式 | 校准集证据选择精确率 | 测试集自动放行精确率 | 实验放行数 | 人工接管 Precision | 人工接管 Recall |
|---|---:|---:|---:|---:|---:|
| BM25 | 95.65%（44/46） | 86.49%（32/37） | 37/90 | 77.36% | 89.13% |
| 混合 | 95.00%（57/60） | 79.63%（43/54） | 54/90 | 88.89% | 74.42% |

表中“自动放行精确率”以来源主题匹配作为代理判断，不能证明答案语义正确；人工接管的正例包括高风险、知识外问题和错误首条来源。混淆矩阵与误放行记录全部保留在原始结果中。

阈值在测试前冻结，测试没有保持95%的目标，所以 **两个模式的自动建议发布门槛均未通过**。系统保留原始阈值，默认将工单交给人工审核，界面明确显示原因；不在这份测试集上反复调阈值追求漂亮结果。表中的放行比例是实验结果，实际应用在当前发布保护下不自动放行。高风险仍优先转人工。

## MiMo真实生成与语义审查

本次实际使用 mimo-v2.5-pro，关闭自动重试，关闭 thinking，每次输出最多1000 tokens。共30次调用，输入 10807 tokens、输出 4324 tokens，未追加付费调用；后续工程复测只复用原始记录。参数依据 [MiMo官方接口说明](https://mimo.mi.com/docs/en-US/usage-guide/passing-back-reasoning_content)。

固定取测试集中前30条通过校准阈值的低风险候选，独立调用生成器；这属于候选生成实验，**没有绕过应用的人工审核保护去展示自动答案**。

| 项目 | 结果 |
|---|---:|
| 合法JSON和预期字段类型 | 30/30 |
| 引用非空、属于当前资料集合且通过租户／版本校验 | 27/30 |
| 被拒绝的无引用输出 | 3/30 |
| 真实请求 P50 / P95 / P99 | 4.23 / 7.63 / 23.97 秒 |

Codex逐条对照实际引用资料做保守语义审查：27条被结构校验接受的答案中，17条核心建议有资料支持，10条存在未支持细节或场景不符。另3条已经在引用校验阶段拒绝。详见 semantic-review.json；它与 generation-raw.json 的哈希绑定。**这是AI审查，不是人工金标准准确率**，不作为服务端的语义校验能力。

典型失败：账号锁定引用VPN资料，并凭空给出15–30分钟；显示器问题引用投影资料并添加Fn+F4；磁盘空间问题引用软件安装资料并增加卸载动作。引用ID合法不能解决这些问题，这也是保留人工审核的实际依据。

## 工程测试与短时HTTP测试

35项自动化测试全部通过，覆盖：
- 知识检索回归、句边界与标题、版本稳定标识；
- 真实扩展故障、索引缺失、模型不匹配、未经运行验证的旧向量、失败恢复；
- 第四条引用返回、非法／跨租户／过期引用、模型超时无重试；
- 模型请求前拒绝错误租户资料、隔离数据库冒烟检查、空数据卷下读取镜像内置资料；
- 校准与发布门槛边界、管理员租户统计、旧记录分母、请求ID关联；
- 小时／日限流清理、旧库迁移、在线备份恢复、重启和并发审批唯一成功。

另运行真实本地HTTP，LLM关闭、BGE已加载。每个工作流包含 POST提交和携工单凭证的GET查询；成功还要求ID一致及请求追踪字段存在。默认发布保护开启。各并发执行100次，每组都是短时测量，不代表稳态容量或生产SLO。
